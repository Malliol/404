# Урок 2. Старая методика проведения. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=3VZObGM6Rrc · 98 мин · [полный текст](../transcripts/002_3VZObGM6Rrc.md)

## О чём урок
Проведение приходной и расходной накладных, формирование движений по регистру «Остатки номенклатуры» и контроль остатков **старой методикой проведения**. Долгое вступление (правила поведения в чате) здесь пропущено.

## Организационные выводы из чата
- Экзамен «на скорость»: времени мало, лишнее лучше не делать или упрощать. Но неверная сумма (не равная количеству × цене) может стоить балла, даже если автопересчёта не требуют.
- Автор продолжает делать быстрый пересчёт сумм, потому что на экзамене он занимает пару минут.

## Быстрый пересчёт сумм (упрощённая версия урока 1)
1. Общий модуль (флаг «Клиент»): одна экспортная процедура, например `РассчитатьСуммуВСтроке(ТекущаяСтрока)`: `Сумма = Цена * Количество`. Условий и параметров нет.
2. В форме документа у табличной части включить **«Подвал»**. Для поля «Сумма» указать путь к данным подвала `Объект.СписокНоменклатуры.Сумма` (в «Объекте», а не в «Элементах»). Итог по колонке считается автоматически, в том числе при удалении и копировании строк.
3. У полей «Количество» и «Цена» обработчик «ПриИзменении» вызывает процедуру. Колонку «Сумма» делают «Только просмотр».
4. Реквизит «СуммаДокумента» не выводят на форму. Перед записью его заполняют итогом по колонке.

## Панели интерфейса — в конфигураторе, а не у пользователя
Настройки панелей, сделанные в пользовательском режиме, действуют только для одного пользователя. На экзамене пользователей может быть несколько (бизнес-процессы, функциональные опции, параметры сеанса). Поэтому интерфейс настраивают **в конфигураторе**: «Интерфейс клиентского приложения» → панель разделов слева, панель функций убрана, панель открытых окон внизу. Тогда кнопка «Стандартные» в настройке панелей возвращает именно эту раскладку.

## Подготовка объектов
- Добавлен справочник «Склады», измерение «Склад» в регистре «Остатки номенклатуры» и реквизит в обеих накладных. Справочник добавлен в подсистемы «Оперативный учёт» и «Бухгалтерский учёт».
- Проверка заполнения у реквизитов: «Склад» обязателен; для строк табличной части обязательны номенклатура, количество, цена, сумма. Нулевое количество запрещают («бессмысленный документ»). Нулевая цена допустима, это определяется условием задачи (в типовых для бесплатного прихода есть отдельные документы).
- Заполнение «СуммаДокумента» итогом перед записью обязательно.

## Проведение: основные свойства документа
- **Проведение:** «Разрешить» почти всегда. «Запретить» — для документов ручной корректировки движений (например, бухгалтерская операция).
- **Оперативное проведение:** при проведении текущим днём ставит текущее время, разводит документы по секундам и запрещает проведение будущей датой. Если в условии есть требование вводить документы будущей датой, оперативное проведение запрещают. Если требования нет, можно ставить любое значение; автор слышал рекомендацию «разрешить, если не противоречит условию». Для начисления зарплаты оперативное проведение всегда запрещают.
- **Удаление движений:** варианты «Не удалять» (плохо: сам следи за удалением), «Удалять автоматически» (удобно, но система удаляет движения до обработки проведения и рано накладывает блокировки, поэтому считается неоптимальным) и «Удалять автоматически при отмене проведения» (по умолчанию). Последний вариант на экзамене использовать всегда. Он удаляет движения при отмене проведения и при пометке на удаление, но не при перепроведении.
- **Запись движений:** оставлять «Записывать только изменённые наборы» нельзя (то есть «Записывать модифицированные» не выбирать). Рекомендуется режим по умолчанию: «Записывать выбранные», а нужным регистрам флаг `Записывать = Истина` выставлять вручную. Так можно управлять тем, какие регистры пишутся.

## Конструктор движений и просмотр движений
- Обработка проведения → конструктор движений: выбрать табличную часть, нажать «Заполнить выражения» (для расходной накладной тип движения — «Расход»).
- Регистр накопления в подсистеме не отмечается флажком, потому что самостоятельная запись запрещена. Флажок можно поставить вручную.
- Из формы документа движения открывают двумя способами:
  1. В конфигураторе: форма → закладка «Командный интерфейс» → «Переход» → флажок у регистра.
  2. В пользовательском режиме: «Настройка панели навигации формы» (кнопка с тремя точками).
  Автор считает, что лучше в пользовательском режиме, потому что регистров может быть 20, и все они в панель не поместятся. Требования на экзамене нет. Для анализа используют отчёт по движениям.

## Контроль остатков по старой методике
Когда проверять и писать движения:
1. Сначала узнают остатки, потом формируют движения.
2. **Момент времени, а не дата документа.** Дату документа использовать нельзя: при нескольких документах на одну дату остатки будут посчитаны неверно (не учтёт ранее проведённые документы). `Момент времени = Дата + Ссылка`, метод `МоментВремени()`.
3. Запрос по табличной части документа «схлопывает» дубли: группировка по номенклатуре со складом, сумма по количеству.
4. Остатки берут из виртуальной таблицы `РегистрНакопления.ОстаткиНоменклатуры.Остатки(&МоментВремени, Номенклатура В (...) И Склад = &Склад)`. Накладывать отбор в параметрах виртуальной таблицы обязательно, чтобы не считать остатки по всей базе.
5. Остатки присоединяют левым соединением к временной таблице документа. Пустые остатки заменяют на 0 через `ЕСТЬNULL`. Поля соединения во временной таблице **индексируют** (`ИНДЕКСИРОВАТЬ ПО`). Это требование оптимизации, которое проверяет экзаменатор.
6. **Не использовать неявное соединение «через точку»** (например, `Склад.Наименование`) в запросе. Получение представлений — отдельная тема, см. ниже.
7. Цикл по выборке: если количество больше остатка, выводится сообщение, взводится флаг отказа. Если не хватает, `Продолжить` вызывается раньше формирования движений: незачем формировать движения для документа, который не проведётся. Для остальных позиций формируют движения.

Сообщения об ошибках:
- Использовать объект `СообщениеПользователю` (шаблоны Ctrl+Q для быстрого ввода).
- Отказ от проведения: `Отказ = Истина`.
- В тексте сообщения нужно выводить **представление** номенклатуры (`НоменклатураПредставление`), а не ссылку. Подстановка ссылки приводит к скрытому запросу в базу внутри цикла — «запрос в цикле» является грубой ошибкой, за неё снимают 2–3 балла, а из 5 это проваленный экзамен.

## Перепроведение и очистка движений
Если документ перепровести с большей датой, старые движения остаются и искажают контроль остатков. Решение: в начале обработки проведения очистить набор записей регистра:
```
Движения.ОстаткиНоменклатуры.Записывать = Истина;
Движения.Записать();      // записали пустой набор
Движения.ОстаткиНоменклатуры.Записывать = Истина;  // флаг сбросился, взводим заново
```
Автор не усложняет код условием «сдвинулась ли дата». Просто удаляет всегда: на экзамене этого не требуют. Альтернатива из чата: `Движения.ОстаткиНоменклатуры.Записать()` вызывает запись только нужного набора и не сбрасывает флаги.

## Блокировки
- В клиент-серверной базе два пользователя могут одновременно прочитать остаток 150 и оба списать 150, получив отрицательный остаток. В файловой базе блокируется вся таблица целиком, поэтому проблему там не воспроизвести. Но решение всё равно нужно описывать.
- **Правило: блокировки накладывать как можно позже**, в нашем случае непосредственно перед запросом остатков.
- Код управляемой блокировки:
  ```
  Блокировка = Новый БлокировкаДанных;
  Элемент = Блокировка.Add("РегистрНакопления.ОстаткиНоменклатуры");
  Элемент.Режим = РежимБлокировкиДанных.Исключительный;
  Элемент.УстановитьЗначение("Склад", Склад);
  Элемент.ИсточникДанных = СписокНоменклатуры;
  Элемент.ИспользоватьИзИсточникаДанных("Номенклатура", "Номенклатура");
  Блокировка.Заблокировать();
  ```
  Для контроля остатков режим блокировки всегда «Исключительный».
- На уровне конфигурации «Режим управления блокировкой данных» нужно поставить «Управляемый». В каркасе стоит «Автоматический», и блокировка не заработает («Использование менеджера блокировок…»). Свойство в самом регистре действует только тогда, когда на уровне конфигурации режим «Автоматический и управляемый». Рекомендуется проставить «Управляемый» и в регистре тоже, хотя оставленное значение не считается ошибкой.
- «Автоматические блокировки» считаются плохими: система блокирует лишнее.

## Дополнительные требования
- В регистре для каждого измерения нужно включить флаг **«Запрет незаполненных значений»** (из чата). Без него снимают баллы.
- Разрешить разделение итогов — см. следующий урок.

## Итог по методикам
- **Старая методика:** запрос на остатки → контроль → формирование движений. Используется часто, когда для движений нужны дополнительные вычисления (например, себестоимость, которую получают запросом).
- **Новая методика:** сначала записать движения, потом проверить остатки. Применима только если в документе достаточно данных для формирования движений. Разбор — в уроке 3.
