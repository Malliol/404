# Урок 5. Расчёт себестоимости по ФИФО / ЛИФО. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=V0zYMdCBDZU · 56 мин · [полный текст](../transcripts/005_V0zYMdCBDZU.md)

## О чём урок
Партионный учёт: списание по ФИФО и ЛИФО в разрезе складов, назначение метода списания через учётную политику (регистром сведений и документом).

## Исправление из прошлого урока
Ресурс «Стоимость» в регистре «Остатки номенклатуры» лучше задавать с теми же параметрами, что и «Сумма» в приходной накладной: **длина 12, точность 2** (а не 10 знаков по умолчанию + 2 для точности). Лучше подстраиваться под границы, которые система обозначила заранее.

## Теория (повторение)
- По средней: общая себестоимость ÷ общее количество × списываемое.
- ФИФО: идём по партиям сверху вниз (от старых к новым): 15 шт. → 10 000 + 10 000 = 20 000.
- ЛИФО: идём снизу вверх: 15 шт. → 20 000 + 5 000 = 25 000.
- Правило из чата: списывать сначала дорогие партии (против ФИФО) налоговая не позволит — закон и экзаменационные требования диктуют порядок по времени поступления, а не по сумме.

## Учётная политика
Объект «Учётная политика» в каркасе — это перечисление методов списания (название странное). **Удалять объекты каркаса нельзя**, про переименование автор не уверен и не рискует.

На экзамене встречаются два варианта хранения политики.

**1. Регистр сведений «УчётнаяПолитика»**
- Периодический, периодичность «в пределах года» (или месяца — как сказано в задаче), режим записи «Независимый» (документов пока нет), основной отбор по периоду.
- Флажок «Регистрировать изменения периодов в плане обмена» к экзамену отношения не имеет.
- Ресурс «МетодСписанияСебестоимости» (тип — перечисление), **обязательно заполнение**.
- Вывести регистр в командный интерфейс (группа команд «Регистры сведений»). Заодно справочник «Склады» перенести в группу команд «Справочники».
- Две записи в год не создать: период приводится к началу года.

**2. Документ «НазначениеУчётнойПолитики»**
- Реквизит «МетодСписания» — проверка заполнения «Выдавать ошибку».
- Проведение разрешено, оперативное проведение запрещено (смысла нет).
- Движения: тот же регистр сведений, который меняют на «Подчинение регистратору». Конструктор движений.
- В «ПередЗаписью» дату документа приводят к началу года (`НачалоГода(Дата)`), чтобы дата документа и период регистра были согласованы.
- Документ вывести в командный интерфейс (группа команд «Документы»).

## Партионный учёт
- Область задачи: себестоимость считается **в разрезе складов** (то же измерение «Склад»).
  - Если по условию склады ведутся, а себестоимость считается по всей компании без складов, потребуется отдельный регистр накопления «Себестоимость товаров». Остатки в одном регистре (старая методика), себестоимость в другом (новая). Это следующий урок.
- В регистр «Остатки номенклатуры» добавлено измерение **«Партия»**, тип — «ДокументСсылка.ПриходнаяНакладная» (документы, которые могут привести товар на склад).
- **Запрет незаполненных значений для партии не ставить**: если реализованы и средняя, и ФИФО/ЛИФО, при расчёте по средней партия остаётся пустой.
- В приходной накладной в движения добавляется `Запись.Партия = Ссылка`.
- Пример: три прихода (ады вдув 10 шт. по 1000 — 1 января; 10 шт. по 2000 — 5 января; бадьян Диана 4 шт. и т. д.) и расход 15 и 7 шт.

## Выбор методики проведения
Старая. Чтобы заполнить партию и стоимость, нужны данные из регистра (запрос и блокировка), поэтому преимущества новой методики пропадают.

## Старая методика с партионным учётом (алгоритм)
1. Очистить движения (`Движения.ОстаткиНоменклатуры.Записывать = Истина; Движения.Записать()`).
2. Взвести флаг записи (лучше непосредственно перед формированием движения, потому что `Записать()` сбрасывает флаг в Ложь).
3. **Блокировка** остатков по складу и номенклатуре. Партию не блокируют: заранее неизвестно, какие партии понадобятся, поэтому блокируются все.
4. Запрос (его отлаживают в консоли запросов):
   - временная таблица с товарами документа (номенклатура, максимум количества);
   - левое соединение с остатками, где выбираются «Партия», «КоличествоОстаток», «СтоимостьОстаток»;
   - **«Итоги» по номенклатуре**: итоговая запись содержит `МАКСИМУМ(Количество)` (количество по документу одинаково во всех строках) и `СУММА(КоличествоОстаток)`;
   - упорядочение партий по моменту времени (`УПОРЯДОЧИТЬ ПО Партия.МоментВремени`): для ФИФО по возрастанию, для ЛИФО по **убыванию** (`УБЫВ`).
   - В консоли запросов удобен способ выгрузки «Дерево».
5. Контроль остатков на уровне **итоговых записей** (обход `ВыборкаНоменклатура` — `Следующий()` встаёт на итоговую запись). Если количество по документу больше суммарного остатка: сообщение (`СтрШаблон("Недостаточно товара %1 в количестве %2", Номенклатура, Разница)`), `Отказ = Истина`, `Продолжить` (не прерывать — нужно проверить все позиции).
6. Обход детальных записей (партий) внутри итоговой: `КоличествоСписать` берётся из итоговой записи.
   - Для партии: `Количество = Мин(КоличествоСписать, КоличествоОстаток)`.
   - Если `Количество = КоличествоОстаток` — списывается вся стоимость партии. **Условие последнего списания**: `Себестоимость = СтоимостьОстаток`.
   - Иначе: `Себестоимость = Количество / КоличествоОстаток * СтоимостьОстаток` (предпочтительный порядок операндов, меньше погрешность).
   - Движение: период = дата документа, вид движения — расход, номенклатура, склад, партия, количество, стоимость.
   - `КоличествоСписать = КоличествоСписать - Количество`. **Об этом легко забыть**, и тогда алгоритм списывает лишнее.
   - Если `КоличествоСписать <= 0` — выход из обхода партий (`Прервать`), иначе в регистр попадут нулевые записи.
7. Проверка деления на ноль не нужна: контроль остатков уже пройден, нулевых остатков в регистре нет.
8. Если по условию отказ уже взведён, формировать движения не имеет смысла, и итерация пропускается (`Продолжить`).

## Метод списания из регистра
- Получение метода в общем модуле нужно, только если он требуется в нескольких документах. На экзамене чаще один документ, поэтому запрос прямо в проведении.
- Запрос к виртуальной таблице `РегистрСведений.УчетнаяПолитика.СрезПоследних(&Период)` (не таблица значений: экзаменатор не любит лишнее расходование памяти).
- Если результат запроса **пустой** — сообщение «Не указан метод списания себестоимости в учётной политике», `Отказ`, выход из обработки проведения. Иначе получить выборку, `Следующий()`, значение — в переменную.
- Для ЛИФО заменить в тексте запроса направление сортировки: `Запрос.Текст = СтрЗаменить(Запрос.Текст, "...", "... УБЫВ")`.
- Полученные результаты в примере совпали с расчётом в Excel: ады вдув 15 шт. → 20 000 (ФИФО) и 25 000 (ЛИФО); для бадьяна Дианы партии списываются в обратном порядке.

## Замечания
- Функция форматирования строки с подстановкой — `СтрШаблон` (в видео случайно названа «формат/стр формат»).
- Конкатенация строк не настолько медленная, чтобы это влияло на решение экзаменационных задач.
- Следующее занятие: то же, но себестоимость считается по всей компании (без склада) — второй регистр накопления, комбинация старой и новой методик.
