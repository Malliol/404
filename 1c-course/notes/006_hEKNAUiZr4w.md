# Урок 6. Расчёт себестоимости по всей компании. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=hEKNAUiZr4w · 65 мин · [полный текст](../transcripts/006_hEKNAUiZr4w.md)

## О чём урок
Та же задача партионного списания (ФИФО/ЛИФО), но с важным изменением в условии: **учёт товаров ведётся по складам, а себестоимость считается по компании в целом** (без разреза по складам). Это требует двух регистров накопления и сочетания двух методик проведения. Дополнительно: услуги в номенклатуре.

## Почему нужны два регистра
Малое изменение условия приводит к архитектурному изменению:
- **«Остатки номенклатуры»**: измерения Номенклатура, Склад; ресурс Количество. **Стоимость и партию убираем**.
- **«Себестоимость товаров»** (новый регистр накопления, подсистема «Оперативный учёт»): измерения Номенклатура, Партия (склада нет); ресурсы Количество, Стоимость.
- На экзамене требуется контролировать остатки **по обоим регистрам**, потому что данные в них могут оказаться несогласованными.
- Для «Остатков номенклатуры» данных документа достаточно, значит **новая методика**. Для «Себестоимости товаров» нужны запросы для партии и стоимости, значит **старая методика**. Обе методики живут в одной обработке проведения.
- Регистр «Себестоимость товаров» нужно вывести в командный интерфейс (группа команд регистров накопления) и поставить флажок отображения.

## Услуги
Условие билетов: «помимо продажи товара могут оказываться дополнительные услуги (например, доставка)».
- Добавить в справочник «Номенклатура» реквизит **«ВидНоменклатуры»** (тип — перечисление «ВидыНоменклатуры»: Товар/Услуга из каркаса). Булев реквизит «Услуга» — неоптимальное решение, за него могут снизить балл.
- Проверка заполнения реквизита — «Выдавать ошибку».
- В приходной накладной запретить выбор услуг: у реквизита «Номенклатура» табличной части в **«Параметрах выбора»** отбор «Вид номенклатуры = Товар» (в поступлении услуги не нужны, в условии они только для продаж).
- В расходной накладной услуги выбираются, но не должны попадать в движения регистров остатков и себестоимости (фильтр по виду номенклатуры в запросах — отработают в следующих уроках).
- Для проверки создана услуга «Доставка товара» и товары «ады вдув обыкновенный» и «бадьян Диана» с видом «Товар».

## Приходная накладная (новая методика, два регистра)
Конструктор не обязателен, можно запросом:
- Запрос по табличной части: Номенклатура, Количество, Сумма (с группировкой), условие по ссылке.
- В запрос в качестве полей добавляют **Период, Склад, Партию (ссылка), `ВидДвижения`** — названия полей запроса должны **точно совпадать с именами измерений/ресурсов регистров** (ошибка в примере: поле «Сумма» вместо «Стоимость»).
- Параметры запроса: склад, период (дата документа), партия.
- Флаги `Записывать = Истина` для обоих регистров.
- Движения: `Движения.ОстаткиНоменклатуры.Добавить...` в цикле по выборке.
- Урок на ошибке: забыли вид движения (`ДобавитьПриход()`/`ДобавитьРасход()`) — запись не заполнялась; `ВидДвиженияНакопления.Приход` лучше указывать явно.

## Расходная накладная, часть 1: регистр «Остатки номенклатуры» (новая методика)
1. Запрос: Номенклатура и Количество из табличной части с группировкой и условием по ссылке. Результат в **временную таблицу `ВТ_Товары`**, поле «Номенклатура» индексируется (используется в условии).
2. Второй запрос в пакете формирует данные для движений: Период, Склад, Номенклатура, Количество, Вид движения (расход) из `ВТ_Товары`.
3. `Движения.ОстаткиНоменклатуры.Записывать = Истина`, `БлокироватьДляИзменения = Истина` (отключает разделитель итогов и обеспечивает правильную блокировку).
4. `Движения.ОстаткиНоменклатуры.Записать()`.
5. Контроль остатков вторым запросом:
   - `Остатки(&Граница, Склад = &Склад И Номенклатура В (ВЫБРАТЬ Номенклатура ИЗ ВТ_Товары))`;
   - условие `КоличествоОстаток < 0`;
   - используется **`Граница` с видом «Включая»** (нужно учесть записанные движения текущего документа);
   - временную таблицу делят между запросами через `МенеджерВременныхТаблиц`: после выполнения первого запроса в менеджере появляется `ВТ_Товары`, второй запрос использует тот же менеджер.
6. Если результат пустой, всё хорошо. Иначе: `Отказ = Истина`, сообщения через `СтрШаблон("Недостаточно товара %1 в количестве %2", Номенклатура, -КоличествоОстаток)`.
7. Если отказ уже взведён, по второму регистру ничего не контролируют и не формируют (`Возврат`). Иначе пользователь получит дублирующие сообщения по обоим регистрам.

## Расходная накладная, часть 2: регистр «Себестоимость товаров» (старая методика)
1. Очистка движений: `Движения.СебестоимостьТоваров.Записывать = Истина; Движения.Записать()` (флаг после записи сбрасывается, взвести заново; запись первого регистра очистка не затрагивает: флаг для него уже сброшен).
2. **Блокировка** регистра «Себестоимость товаров» по номенклатуре (склада нет). Партии не блокируют: заранее неизвестно, какие нужны. Режим «Исключительный», источник данных — табличная часть.
3. Запрос остатков:
   - использовать существующий менеджер временных таблиц с `ВТ_Товары` (не повторять выборку табличной части);
   - левое соединение `РегистрНакопления.СебестоимостьТоваров.Остатки(&МоментВремени, Номенклатура В (...))` по номенклатуре;
   - поля: Партия, КоличествоОстаток, СтоимостьОстаток (всё через `ЕСТЬNULL(..., 0)`, так как для нового товара остатков может не быть);
   - здесь **момент времени, а не граница**: движения текущего документа учитывать не нужно (они очищены);
   - итоги по номенклатуре: `МАКСИМУМ(Количество)` и `СУММА(КоличествоОстаток)`;
   - упорядочивание по `Партия.МоментВремени` (ФИФО — по возрастанию).
4. Контроль на уровне итоговых записей: количество по документу больше суммарного остатка → сообщение (с представлением номенклатуры), `Отказ`, `Продолжить`. Прерывать нельзя: нужно проверить все позиции. Если отказ, детальные записи не обходят и движения не формируют.
5. Списание по партиям (как в уроке 5): `КоличествоСписать` из итоговой записи; в цикле по партиям:
   - `Количество = Мин(КоличествоСписать, КоличествоОстаток)`;
   - если `Количество = КоличествоОстаток`, берётся вся стоимость партии (**условие последнего списания**), иначе `СтоимостьОстаток / КоличествоОстаток * Количество` (порядок операндов можно оставить обычным: проблему копеек закрывает условие последнего списания);
   - добавляют `ДобавитьРасход()`, заполняют период, номенклатуру, партию, количество, стоимость;
   - `КоличествоСписать = КоличествоСписать - Количество`, выход из цикла при нуле.
6. Проверка деления на ноль не нужна, но по просьбе зрителей показана для нулевого остатка по партии: сообщение «Обнаружен нулевой остаток по партии %1», `Отказ`, `Прервать`. Автор подчёркивает, что на экзамене этого не требуют.

## Метод списания из учётной политики
Два способа (оба считаются допустимыми, Белоусов принимает оба):
- Запрос к `СрезПоследних` — основной способ (проверка на пустой результат).
- Функция `РегистрыСведений.УчетнаяПолитика.ПолучитьПоследнее(Дата)` возвращает структуру. Если записи на дату нет, поле имеет значение по умолчанию (для перечисления — пустая ссылка). Проверка: `Если Метод = Перечисления.УчетнаяПолитика.ПустаяСсылка()` → сообщение «Не указан метод списания себестоимости», `Отказ`, `Возврат`.

Порядок упорядочивания (**важная ошибка из урока**): без `УПОРЯДОЧИТЬ ПО Партия.МоментВремени` порядок партий случайный. Для ФИФО указывают по возрастанию, для ЛИФО в тексте запроса заменяют на `... УБЫВ` через `СтрЗаменить`.

Проверка на примере: приходы на разные склады на 1 и 5 января; продажа 15 шт. по ФИФО списала 10 шт. с первой партии (10 000) и 5 шт. со второй (10 000) — как в Excel (20 000). Для ЛИФО порядок обратный.

## Замечания и ответы на вопросы чата
- Решение «одним регистром с итогами» неправильно: себестоимость в разрезе склада здесь не имеет смысла.
- Порядок измерений в регистре (склад впереди номенклатуры): утверждение зрителя об оптимальности без источника автор принять не готов.
- Порядок условий отбора в параметрах (сначала склад) на экзамене значения не имеет.
- `ЕСТЬNULL` нужен, потому что при левом соединении без совпадений приходит `NULL`, с которым нельзя делить и умножать.
- Бухгалтерский учёт будет позже, сначала прорешиваются задачи оперативного учёта (актуальные билеты берутся из Telegram-чата подготовки).
- Следующее занятие в тот же день: отчёт «Остатки товаров на складах».
