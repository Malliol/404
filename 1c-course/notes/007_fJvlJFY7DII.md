# Урок 7. Отчёт «Остатки товаров на складах», часть 1. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=fJvlJFY7DII · 65 мин · [полный текст](../transcripts/007_fJvlJFY7DII.md)

## О чём урок
Первый отчёт на СКД (система компоновки данных) из билета № 1: «Остатки товаров на складах». Попутно доработана работа с услугами из урока 6.

## Работа над ошибками: услуги в расходной накладной
Если в расходной накладной выбрать услугу «Доставка товара» (хоть 1000 шт.), проведение выдаёт «Недостаточно товара». Услуги не должны участвовать ни в движениях регистров «Остатки номенклатуры» и «Себестоимость товаров», ни в контроле остатков.

Решение: в запросе, формирующем временную таблицу `ВТ_Товары`, добавить условие
```
ГДЕ Номенклатура.ВидНоменклатуры = ЗНАЧЕНИЕ(Перечисление.ВидыНоменклатуры.Товар)
```
В регистр продаж (когда он появится) услуги, напротив, нужно было бы записывать.

## Экзаменационное требование к отчёту
Отчёт нужно воспроизвести **точь-в-точь по образцу из билета**: заголовок, названия колонок, отступы, наличие или отсутствие итогов, жирное начертание. Любое расхождение (например, «Количество» вместо «Кол-во», лишние итоги, нет отступа) — повод снять балл. Актуальные билеты берутся из Telegram-чата подготовки (ссылка в описании видео).

Образец: заголовок «Остатки товаров на дату»; колонки «Склад», «Номенклатура», «Кол-во»; склад жирным, номенклатура с отступом, итогов нет, заголовки колонок жирные.

## Построение отчёта
1. Объект «Отчёт» → «Остатки товаров», подсистема «Оперативный учёт», **схема компоновки данных**.
2. Запрос: `РегистрНакопления.ОстаткиНоменклатуры.Остатки` — Номенклатура, Склад, КоличествоОстаток (количество).
3. Закладка «Ресурсы»: кнопка «>>» (добавить все). Автор: в 99% случаев её и нужно нажимать.
4. Параметр «Период» — выводится в пользовательские настройки (флажок «Включать в пользовательские настройки»).
5. Настройки → структура: группировка «Склад» → вложенная группировка «Номенклатура» (либо детальные записи). Выбранные поля: Склад, Номенклатура, Количество. Группировка без выбранных полей ничего не выведет.
6. Заголовок поля «Количество» → «Кол-во» (в выбранных полях: ПКМ → «Установить заголовок»).
7. Расположение полей группировок: «Отдельно и только в итогах» (получаются отдельные колонки «Склад» и «Номенклатура»). Общие итоги отключаются в «Других настройках» (расположение общих итогов — «Нет»). Если вместо группировки по номенклатуре выбрать детальные записи, ресурсы можно не использовать, но тогда итоги по складам исчезнут.
8. Нужно, чтобы по складам итоги были, а в образце их нет: уточняется по образцу билета. Для варианта без итогов по складам убрать ресурсы, а вместо группировки «Номенклатура» использовать детальные записи.

## Заголовок отчёта
Через свойство «Заголовок» дату отчёта вывести нельзя. Способ 1 (макеты):
1. В структуре отчёта вверху добавить группировку без поля (детальные записи) с названием «Заголовок», использование — «Дополнительная информация». Флажок «Выводить заголовок» в других настройках снять.
2. На закладке «Макеты» создать макет с областью-ячейкой «Остатки товаров на [Период]». Сделать текст жирным, шрифт 10.
3. «Добавить макет группировки»: тип макета «Заголовок», привязать к группировке «Заголовок».
4. В ячейке-шаблоне заполнить параметр «Период» (свойство ячейки → «Заполнение: шаблон», параметр `Период`, формат даты `ДФ=dd.MM.yyyy`).
5. Параметры отчёта на экране скрыть: в других настройках «Вывод параметров — Не выводить».
6. Чтобы у заголовка не было границ ячеек, у макета группировки отключить макет оформления («Не использовать макет оформления»). Идея из чата.
7. Отступ перед «Остатки товаров» делают пробелами или отдельной ячейкой.

Проблема: если параметр «Период» не используется, при вычислении выражения (например, `КонецПериода(&Период, "День")`) появляется ошибка. Обходной путь: «Использование — Всегда». Тогда пустая дата выводится как «01.01.0001». Дополнительно можно подставлять текущую дату:
```
ВЫБОР КОГДА &Период = ДАТАВРЕМЯ(1,1,1) ТОГДА КонецПериода(ТекущаяДата(), "День")
ИНАЧЕ КонецПериода(&Период, "День") КОНЕЦ
```

## Остатки на конец дня
Остатки на дату без времени — это остатки на начало дня, поэтому движения того же дня не учитываются. Правильное поведение: привести параметр «Период» к концу дня — в параметре «Период» выражение `КонецПериода(&Период, "День")`. Тогда отчёт на 16 января учитывает документы за 16 января. На экзамене это нужно уточнять по условию.

## Способ 2: заголовок программно (модуль отчёта)
Не требуется на экзамене (Белоусова устраивает макет), но показан как более гибкий:
1. Обработчик `ПриКомпоновкеРезультата(ДокументРезультат, ДанныеРасшифровки, СтандартнаяОбработка)`.
2. В `КомпоновщикНастроек.ПользовательскиеНастройки.Элементы` обойти элементы в цикле и найти нужный параметр:
   - проверить, что тип элемента — `ЗначениеПараметраНастроекКомпоновкиДанных` (у отбора такого свойства нет);
   - использование = Истина;
   - `Элемент.Параметр = Новый ПараметрКомпоновкиДанных("Период")`.
3. Значение параметра может быть неопределено (флажок снят), стандартной датой начала (`СтандартнаяДатаНачала`, берут `.Дата`) или датой.
4. Дата отчёта: если `Неопределено` — конец текущего дня, если `СтандартнаяДатаНачала` — её `.Дата`, иначе значение.
5. Заголовок: `"    Остатки товаров на " + Формат(ДатаОтчета, "ДФ=dd.MM.yyyy")`, затем `КомпоновщикНастроек.Настройки.ПараметрыВывода.УстановитьЗначениеПараметра("Заголовок", ...)`.
6. Метод `Получить(индекс)` для поиска параметра ненадёжен: нужно имя, а метод принимает индекс.

## Условное оформление
Чтобы заголовки колонок «Склад», «Номенклатура», «Кол-во» были жирными, используют условное оформление: оформляемые поля — три колонки, оформление — полужирный шрифт, условие применения — «Только в заголовках полей» (снять остальные флажки). Автор сначала забыл про жирное начертание, зрители подсказали.
