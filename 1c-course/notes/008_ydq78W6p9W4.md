# Урок 8. Отчёт «Остатки товаров на складах», часть 2. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=ydq78W6p9W4 · 46 мин · [полный текст](../transcripts/008_ydq78W6p9W4.md)

## О чём урок
Доработка отчёта «Остатки товаров на складах» из прошлого урока: условное оформление, итоги по группировкам, параметр «Период» и правильный расчёт остатков на дату. Автор исправляет свои ошибки и по комментариям зрителей упрощает решение.

## Условное оформление
- Полужирное начертание заголовков: достаточно оформить **все заголовки полей**, а не перечислять три поля (вдруг добавится ещё одно). Условие применения — «Только в заголовках полей».
- Числовые ресурсы (количество) прижимаются влево во всех билетах: новый элемент условного оформления, горизонтальное положение — «Влево», оформляемое поле — «Количество»; область использования ограничить группировкой и общим итогом, чтобы при выводе параметров и отбора формат не ломался. Автор отмечает, что практического смысла в выравнивании влево нет — это просто проверка умения пользоваться условным оформлением.

## Как убрать итог по складу
Автор сначала убрал «Количество» из ресурсов и использовал детальные записи вместо группировки «Номенклатура», но это плохое решение: если пользователь переставит группировки (сначала номенклатура, потом склады), отчёт будет выглядеть непонятно. Числовые показатели по смыслу являются ресурсами. Варианты правильнее:
1. Закладка «Ресурсы» → «Рассчитывать по»: только для группировки «Номенклатура». Минус: пользователю закладка недоступна.
2. **Лучший вариант:** в настройках группировки «Склад» → «Другие настройки» → расположение итогов — «Нет». Пользователь может сам включить итоги, поменяв настройки варианта.

## Параметр «Период» и заголовок
- Ошибка прошлого урока: оставлено лишнее выражение для периода, не удалено.
- Параметр «Период» по умолчанию можно включить и задать значение прямо на закладке «Параметры» (флажок «Использование — Всегда»). Пользователь тоже может сохранить своё значение: оно запоминается при **закрытии отчёта** (пользовательская настройка приоритетнее настройки конфигуратора). Параметр по умолчанию автор рекомендует задать «на всякий случай», хотя экзаменатор на это вряд ли смотрит.
- Обработчик `ПриКомпоновкеРезультата` решает проблему, когда параметр не используется или пуст. Но зритель справедливо заметил: если в настройках параметра выбрать «Использование — Всегда» и «Запрещать незаполненные значения», обработчик не нужен: заголовок можно сделать макетом (см. урок 7).

## Остатки на дату: разбор проблемы
Остатки на дату без времени считаются на начало дня, поэтому документы за этот день не попадают в отчёт. Автор пробовал разные решения и пришёл к выводу, что простого выражения недостаточно:

1. Выражение `КонецПериода(&Период, "День")` не учитывает последнюю секунду дня.
2. Добавление секунды (`ДобавитьКДате(КонецПериода(...), "Секунда", 1)`) учитывает последнюю секунду, но ломает «Стандартную дату начала»: «Начало этого дня» превращается в «начало завтрашнего», «Начало этой недели» — во вторник и т. д.
3. Убрать у параметра тип «СтандартнаяДатаНачала» нельзя в конфигурации СКД: можно выбрать только «поле компоновки данных» или ту же стандартную дату. Переопределение формы отчёта (своё поле «Период» типа «Дата», своя кнопка «Сформировать», программное формирование) — слишком сложно для экзамена.

**Вывод автора (проверенный экзаменом вариант):** никаких выражений для периода не писать. Тип параметра «Период» оставить по умолчанию (**Дата и время**), состав даты — «Дата и время», выражение пустое. Пользователь видит время, и по значению сразу понятно: 00:00:00 — остатки на начало дня, 12:00:00 — на указанный час. «Вся вышеописанная оптимизация оказалась лишней.» Идея зрителя (использовать конец стандартного периода) автор не успел проверить.

## Пустая дата и актуальные остатки
- Если снять флажок или указать пустую дату, остатки считаются на «актуальную дату» — 1 ноября 3999 года, и в отчёт попадают документы будущей датой (чтобы проверить, у документа поступления отключили оперативное проведение и провели его в 3999 году).
- Решение: параметру «Период» поставить **«Использование — Всегда»** (флажок снять нельзя) и **«Запрещать незаполненные значения»** (пустую дату нельзя задать). Тогда заголовок, сделанный макетом, всегда корректен, и обработчик `ПриКомпоновкеРезультата` не нужен. Флажок «Использование» остаётся включённым (смысла в «выключено» нет, отчёт всё равно не запустится).
- Отдельные «особые» заголовки (актуальные остатки и т. п.) придумывать не нужно: в билете только «Остатки товаров на дату».

## Три способа получить значение параметра периода из пользовательских настроек
Нужны при программном формировании заголовка (обработчик `ПриКомпоновкеРезультата`). Цикл по `КомпоновщикНастроек.ПользовательскиеНастройки.Элементы` рекомендуется прерывать (`Прервать`) после нахождения.

1. **Обход элементов** (урок 7): сравнение `Элемент.Параметр = Новый ПараметрКомпоновкиДанных("Период")` с проверкой типа элемента и использования.
2. **Через `КомпоновщикНастроек.ПолучитьНастройки()`**: возвращает копию настроек со всеми применёнными пользовательскими и фиксированными настройками (фиксированные — например, заданные программно при открытии отчёта). Затем `Настройки.ПараметрыДанных.НайтиЗначениеПараметра(Новый ПараметрКомпоновкиДанных("Период"))` и проверка `Использование`. Не самый оптимальный способ, но короткий.
3. **Через идентификатор пользовательской настройки** (так сделано в типовых конфигурациях, автор считает его лучшим):
   ```
   Параметр = КомпоновщикНастроек.Настройки.ПараметрыДанных.Элементы.Найти("Период");
   Если Параметр <> Неопределено Тогда
       Элемент = КомпоновщикНастроек.ПользовательскиеНастройки.Элементы.Найти(Параметр.ИдентификаторПользовательскойНастройки);
       Если Элемент.Использование Тогда Значение = Элемент.Значение; ...
   ```
   Здесь `Найти` принимает **идентификатор**, а не имя параметра: сначала находят параметр данных по имени, берут его `ИдентификаторПользовательскойНастройки`, затем ищут элемент пользовательских настроек.

Все три способа в примере вернули одинаковую дату (19 января, начало этого дня).

## Прочее
- Методику замены на пользовательский параметр в «Практическом пособии разработчика» (там период — начало и конец, поэтому конец периода приводят к последней секунде) автор считает другим случаем (оборотный отчёт).
- Рекомендуется открыть любой типовой отчёт и посмотреть `ПриКомпоновкеРезультата`: там происходит много интересного.
- Следующее занятие: задача оперативного учёта из билета № 2 (решение и отчёт, быстрее и без разбора каждой галочки). Билеты — в закреплённом сообщении Telegram-группы.
