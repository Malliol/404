# Урок 10. Контроль остатков по партиям. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=MyoJeDH63Zo · 48 мин · [полный текст](../transcripts/010_MyoJeDH63Zo.md)

## О чём урок
Задача оперативного учёта из экзаменационного билета № 2: складской учёт не ведётся, в расходной накладной пользователь указывает **партию** (приходную накладную), из которой списывается товар. Контроль остатков и себестоимость считаются в разрезе партий. Отчёт по этой задаче — в следующем уроке. Попутно разобрано, как убрать пустую строку в заголовке отчёта.

## Пустая строка между заголовком и шапкой таблицы (вопрос из прошлого урока)
Если две группировки расположены на одном уровне, СКД рисует между ними пустую строку. Способы убрать:
1. Сформировать отчёт программно (автор не проверял).
2. Нарисовать макет заголовка группировки (позже).
3. **Вложить одну группировку в другую.** Порядок действий:
   - группировка «Заголовок» (детальные записи, без варианта использования «Дополнительная информация»);
   - на закладке «Выбранные поля» развернуть авто-поле, оставить только «Количество»;
   - задать группировке заголовок, чтобы связать её с макетом;
   - сделать группировку «Склад» подчинённой этой группировке;
   - для группировки «Склад» включить макет оформления («Основной»), иначе пропадут границы ячеек (отключённый макет оформления у родителя действует на вложенные).
   - Заголовок размещается в нужной ячейке макета (сдвиг пробелами).

Автор подчёркивает, что на экзамене это не важно: пустая строка в образце билета 2 есть, и убирать её не нужно. Это просто вопрос из любопытства.

## Условие задачи
«Складской учёт товаров не ведётся.» В табличной части расходной накладной для каждого товара указывается партия (приходная накладная), и остатки контролируются в разрезе номенклатуры и партии.

## Изменения конфигурации
- В регистре «Остатки номенклатуры»: убрать измерение «Склад», измерение «Партия» (тип «ДокументСсылка.ПриходнаяНакладная»), ресурсы — Количество, Стоимость.
- Регистр «Себестоимость товаров» **не нужен**: остатки и себестоимость ведутся в одинаковом разрезе (номенклатура + партия), поэтому достаточно одного регистра. Сначала у регистра снимают регистраторы, затем удаляют его.
- Убрать реквизит «Склад» из шапок обеих накладных.
- В табличной части расходной накладной добавить реквизит **«Партия»** (тип — приходная накладная) и вывести его на форму. Выбор партии для услуги бессмысленен, но ограничивать это условным оформлением на экзамене не нужно, как и ограничивать выбор партий (только не списанные, с остатком нужного товара). Времени на экзамене мало, и требований на управляемые формы такого уровня нет.
- Весь код документов (обработки проведения) удаляется и пишется заново (полезно повторить).

## Проведение приходной накладной
Допустимо конструктором движений (так делает и Белоусов); свёртка строк улучшает, но не обязательна. Партия = ссылка на приходную накладную (при перепроведении старых документов партия заполнится заново — их нужно перепровести).

## Проведение расходной накладной (старая методика)
Старая методика: нужна себестоимость, вычисляемая запросом.
1. Очистить движения регистра, взвести флаг записи.
2. Запрос по табличной части: Номенклатура, Партия, Количество, Сумма (с группировкой), условие по ссылке → временная таблица `ВТ_Товары`. Индексировать поля соединения — **Номенклатура и Партия**.
3. Левое соединение с `Остатки(&МоментВремени, (Номенклатура, Партия) В (ВЫБРАТЬ Номенклатура, Партия ИЗ ВТ_Товары))`. Остатки считаются по партиям из документа. Здесь **момент времени, а не граница** (движения документа очищены).
4. Поля: номенклатура и партия (и их представления для сообщений), количество, период (дата документа), `ЕСТЬNULL(КоличествоОстаток, 0)`, `ЕСТЬNULL(СтоимостьОстаток, 0)`. `ЕСТЬNULL` нужен для правых полей при левом соединении, чтобы не получать `NULL`.
5. Контроль остатков: если количество больше остатка → `Отказ`, сообщение через `СтрШаблон("Недостаточно товара %1 по партии %2 в количестве %3", НоменклатураПредставление, ПартияПредставление, Разница)`. При отказе — `Продолжить`.
6. Себестоимость: **условие последнего списания** (если списывается вся партия — берётся вся стоимость остатка), иначе `Количество / КоличествоОстаток * СтоимостьОстаток` (оптимальный порядок операндов, но при условии последнего списания можно не следить).
7. **Блокировка** нужна, так как по запросу остатков формируются движения. Это первый случай, когда блокируем и партию: теперь известно, какие партии нужны (в отличие от ФИФО, где партии вычислялись). Режим «Исключительный», источник данных — табличная часть, `ИспользоватьИзИсточникаДанных` для «Номенклатура» и «Партия».

Проверка деления на ноль не нужна: к этому месту контроль остатков уже пройден, количество остатка не нулевое. Автор подчёркивает, что Белоусов и курсы 1С её не делают.

## Услуги в запросе
При проведении выяснилось, что услуга «Доставка товара» ломает контроль («Недостаточно товара…»). Сначала ограничили табличную часть условием «Вид номенклатуры = Товар». Затем выяснилось, что услуги нужно фиксировать в регистре продаж. Поэтому условие убрали:
- в запросе остатков виртуальной таблицы условие по виду номенклатуры отсекает услуги;
- в `ВТ_Товары` выбирается поле «ВидНоменклатуры»;
- контроль остатков и движения по «Остаткам номенклатуры» выполняются только `Если Выборка.ВидНоменклатуры = Перечисления.ВидыНоменклатуры.Товар`;
- движения регистра продаж формируются для всех позиций, включая услуги.

## Регистр «Продажи» (регистр накопления, вид «Обороты»)
Отчёт по задаче включает «Сумму продажи», которой нигде нет. Данные для отчёта **нельзя брать из документа** (нарушение требований), их нужно брать из регистра. Поэтому создаётся оборотный регистр «Продажи».
- Почему не «Остатки номенклатуры»: продажи фиксируются в момент продажи и ничего не накапливается и не списывается — это обороты.
- Измерение: Номенклатура; ресурсы: Количество, СуммаПродажи, **Себестоимость**. Поле «Себестоимость» дублирует данные регистра остатков **намеренно для оптимизации**: отчёт строится по одному регистру без соединений и группировок (вычисляемые поля — на основе ресурсов). Минус: возможная несогласованность данных, но в типовых конфигурациях делают так же.
- Заполнение движений: в той же выборке цикла, где формируются расходные движения: `Движения.Продажи.Добавить()` (у оборотного регистра нет вида движения). Заполняют номенклатуру, период, количество, сумму продажи, себестоимость. Для услуг себестоимость равна 0.
- **Флаг `Движения.Продажи.Записывать = Истина` обязателен** (без него данные не записываются). Очищать движения регистра продаж и блокировать его не нужно: остатки по нему не контролируются.
- Приходная накладная в регистр продаж ничего не пишет.

## Замечания
- «Что делает `СтрШаблон`»: в справке функции (Ctrl+F1) объяснено: `%1` — первый параметр, всего до 10 параметров.
- Следующее занятие: отчёт по продажам по этому билету.
