# Урок 11. Отчёт по продажам. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=ftDwCsulOi4 · 48 мин · [полный текст](../transcripts/011_ftDwCsulOi4.md)

## О чём урок
Доработка движений в регистр «Продажи» (схлопывание дублей) и построение отчёта «Продажи товаров» по билету № 2 на СКД с вычисляемыми полями.

## Исправление: дубли номенклатуры в регистре продаж
Зритель заметил: если в расходной накладной одна номенклатура списывается из двух партий, в регистре «Продажи» появляются две записи с одинаковыми измерениями. Это неприятно, и экзаменатор может снизить балл.

Решение — **итоги в запросе**:
- Во втором запросе (остатки по партиям) на закладке «Итоги» номенклатура — группировочное поле; итоговые поля: `СУММА(Количество)` и `СУММА(СуммаПродажи)` (для итоговой записи).
- Итоговая запись нужна для регистра продаж, а детальные записи (партии) — для контроля остатков и движений регистра остатков.
- Код обхода: внешний цикл по `ВыборкаНоменклатура = РезультатЗапроса.Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам)`, внутренний — `ВыборкаДетальныеЗаписи = ВыборкаНоменклатура.Выбрать()`. В детальной выборке выполняют контроль остатков и формируют движения «Остатков номенклатуры», в итоговой — движение «Продаж».
- Себестоимость в продажах: накапливается в переменной `ИтогоСебестоимость`, увеличиваемой **на `Движение.Стоимость`** (уже округлённое по точности ресурса), а не на вычисленную переменную, иначе накопленная сумма разойдётся с регистром остатков.
- Период в итоговой записи пуст (`NULL`): в итоговой записи его нет, поэтому `Движение.Период = Дата` (дата документа), а не берём из выборки.
- Альтернатива из чата: пакет запросов с разными выборками и группировками, как в типовых. Автор не считает это нужным.

## Отчёт «Продажи товаров» (билет № 2)
Данные берутся из регистра «Продажи» (в нём специально хранятся все нужные поля: номенклатура, количество, сумма продажи, себестоимость).

**Запрос:**
- Источник: `РегистрНакопления.Продажи.Обороты` с **периодичностью «Авто»** — появляются поля `ПериодДень`, `Регистратор` и т. д.
- Поля: Номенклатура, ВидНоменклатуры, Количество, Продажа (СуммаПродажи), Себестоимость.
- Для вычисления сроков берутся агрегаты:
  - `МИНИМУМ(ПериодДень)` как «ДатаПервойОтгрузки»;
  - `МАКСИМУМ(ПериодДень)` как «ДатаПоследнейОтгрузки»;
  - `КОЛИЧЕСТВО(РАЗЛИЧНЫЕ Регистратор)` как «КоличествоОтгрузок».
- Для проверки заводятся данные: разные номенклатуры, документы на разные даты.

**Вычисляемые поля в СКД** (закладка «Вычисляемые поля» набора данных), по правилам билета:
- **Прибыль** = `Продажа - Себестоимость`.
- **Интервал** = (дата последней отгрузки − дата первой отгрузки) ÷ количество отгрузок; если отгрузка одна, выводится слово «Разовая»:
  ```
  ВЫБОР КОГДА КоличествоОтгрузок = 1 ТОГДА "Разовая"
  ИНАЧЕ РазностьДат(ДатаПервойОтгрузки, ДатаПоследнейОтгрузки, "День") / КоличествоОтгрузок КОНЕЦ
  ```
  Проверка на деление на ноль не нужна: при нулевом количестве отгрузок записей не было бы. Вместо `ВЫБОР` можно использовать условное оформление (выводит слово при значении 0) — подходы равноценны.
- **Срок** = количество дней от даты последней отгрузки до конца периода отчёта: `РазностьДат(ДатаПоследнейОтгрузки, &КонецПериода, "День")`. «КонецПериода» — параметр, создаваемый таблицей оборотов автоматически. Для **услуг срок не выводится** (зритель заметил), поэтому: `ВЫБОР КОГДА ВидНоменклатуры = Значение(Перечисление.ВидыНоменклатуры.Товар) ТОГДА ... ИНАЧЕ 0 КОНЕЦ` (для этого в запрос добавлено поле «ВидНоменклатуры»).

В примере функция называлась `РазностьДат` (опечатка в видео).

**Настройки:**
- Служебные поля (дата первой отгрузки, дата последней, количество отгрузок) нужны только для расчёта, их скрывают: свойство «Ограничение поля» (флажок «Выбор»/«Условие»/…), чтобы они не мешали пользователю в списке доступных полей.
- Ресурсы: количество, прибыль, продажа, себестоимость. Поля «Интервал» и «Срок» ресурсами не делают (суммировать их бессмысленно). Допустимо и не добавлять ресурсы, но в реальной работе ресурсы нужны для гибкости пользователя.
- Параметр «Период» типа **«Стандартный период»**; выражения для параметров: `НачалоПериода = &Период.ДатаНачала`, `КонецПериода = &Период.ДатаОкончания` (дата окончания уже приведена к последней секунде). Параметры «НачалоПериода» и «КонецПериода» из пользовательских настроек убирают (отключить флажки использования), пользователю запрещают выключать период и оставлять его пустым.
- Структура: **без группировок, только детальные записи** («простыня»).
- Выбранные поля — в порядке из образца: Номенклатура, Количество, Себестоимость, Продажа, Прибыль, Интервал, Срок.
- Авто-позиция ресурсов: по умолчанию «После всех полей», поэтому «Интервал» и «Срок» оказываются в середине. Решение: выключить авто-позицию ресурсов (свойство отчёта) либо убрать эти поля из ресурсов.
- Общие итоги отключаются (расположение итогов — «Нет»).
- **Условное оформление:** заголовки полей — полужирный шрифт; числа — горизонтальное положение «Влево», формат с точностью 0 знаков после запятой. Не нужно менять точность ресурсов в регистре: в регистре должно остаться два знака, а округление до целых делается оформлением отчёта.
  - Условное оформление лучше задавать **для группировки (детальных записей)**, а не для всего отчёта: оформление всего отчёта перекрывает формат даты в шаблоне заголовка (заголовок показывал некорректную дату). Настройки можно переносить мышкой между группировками (урок 12).
- **Заголовок** отчёта: как в уроке 7 (группировка «Заголовок» с «Дополнительной информацией», макет группировки). Текст «Продажи товаров за период с [НачалоПериода] по [КонецПериода]» с форматом даты; ячейки без оформления («Без оформления») — граница ячеек исчезает. Пустая строка под заголовком в образце есть.
- **Сортировка** по номенклатуре в группировке детальных записей (в этом уроке сделана по номенклатуре, но в уроке 12 выясняется, что нужен ещё вид номенклатуры).
